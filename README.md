# Pravoe Delo — сайт адвокатского бюро

Статический сайт на [Astro](https://astro.build) на трёх языках (RU / UZ / EN) со светлой и тёмной темой. Публикуется на GitHub Pages. Контент редактирует заказчик через [Pages CMS](https://pagescms.org) — инструкция для него в [docs/КАК-РЕДАКТИРОВАТЬ.md](docs/КАК-РЕДАКТИРОВАТЬ.md).

## Команды

Нужен Node 22.18+ (в CI — Node 24): скрипты в `scripts/`, `tests/` и модули `src/content/*.ts` запускаются напрямую как `.ts` через встроенное в Node удаление типов. Поэтому в этих файлах допустим только «стираемый» TypeScript — без `enum`, `namespace` и параметров-свойств в конструкторах.

| Команда | Что делает |
| --- | --- |
| `npm install` | установка зависимостей |
| `npm run dev` | локальный сервер: http://localhost:4321/PD/ |
| `npm run check` | проверка типов TypeScript и Astro |
| `npm run check:content` | проверка всех файлов контента и медиатеки, отчёт на русском |
| `npm run build` | проверка контента + сборка в `dist/` |
| `npm run preview` | просмотр собранного сайта |
| `npm run test:content` | тесты проверки контента на заведомо сломанных данных |
| `npm run test:smoke` | смоук-тест собранного сайта в браузере (нужны `npm run build` и `npx playwright install chromium`) |
| `npm test` | оба набора тестов |
| `npm run cms:generate` | пересобрать `.pages.yml` из схемы контента |
| `npm run cms:check` | проверить, что `.pages.yml` совпадает со схемой (запускается в CI) |
| `npm run icons:generate` | пересобрать `src/icons/icons.ts` из Lucide и Simple Icons |
| `npm run shots -- --w=1440,390 --theme=dark,light --lang=ru --page=home` | скриншоты в `screenshots/` (в git не попадают). По умолчанию все 4 ширины и обе страницы; флаги `--full=0` (только первый экран), `--menu` (снимок открытого меню на узких экранах), `--clip=Y:H`; адрес и папка — переменные `SHOTS_URL` и `SHOTS_DIR`. Нужен запущенный `npm run dev` |

## Как устроено

### Контент

- **Файлы.** `src/content/*.yaml` — весь контент сайта. Каждый переводимый текст хранится как `{ ru, uz, en }`; если `uz` или `en` пусты, показывается `ru`. Контакты, ссылки и названия клиентов — обычные строки, одни на все языки.
- **Схема.** `src/content/schema.ts` — основное описание структуры (Zod 4): обязательные поля, форматы, лимиты длины и количества, русские подписи полей, список иконок и соцсетей, языки (`LANG_META`). Поля проверяются строго: опечатка в названии поля — ошибка, а не молчаливый пропуск.
- **Проверка** — `src/content/validate.ts`. Запускается перед сборкой (`scripts/check-content.ts`) и повторно при сборке (`src/lib/content.ts`). Ловит:
  - пустые и повреждённые файлы;
  - лишние поля;
  - неизвестные вставки `{…}` в текстах;
  - фото не из медиатеки, а также фото с расширением в смешанном регистре и битые файлы (проверка через sharp);
  - заглушки и непереведённые поля — это предупреждения. Со строгим режимом (`CONTENT_STRICT=1`) заглушки контактов становятся ошибками.
- **Формы Pages CMS** — файл `.pages.yml`, генерируется из схемы командой `npm run cms:generate`, руками не правится. CI падает, если файл устарел.

**После изменения схемы:**
1. обновить YAML в `src/content/`;
2. выполнить `npm run cms:generate` и закоммитить `.pages.yml`;
3. выполнить `npm run check:content` и `npm test`.

**Новая иконка или соцсеть:** добавить её в `ICONS` / `SOCIALS` в `schema.ts`, затем выполнить `npm run icons:generate`. Иконки интерфейса, которых нет в контенте, перечислены в `scripts/generate-icons.ts`.

**Маркеры заглушек** — `PLACEHOLDER_MARKERS` в `src/content/validate.ts`. Уберите маркер, если реальные данные совпадут с ним.

### Фото

`src/assets/uploads/` — фото и логотипы клиентов, сюда же их загружает Pages CMS.
- В YAML путь хранится как `/uploads/<путь внутри папки>`; подпапки поддерживаются.
- Расширение должно быть целиком строчным или целиком заглавным (`.jpg` / `.JPG`).

### Код

- **`src/lib/`:**
  - загрузка контента и фото (`content.ts`);
  - i18n — `tr`, `lines`, ссылки на языковые версии (`i18n.ts`);
  - типографика: неразрывные пробелы в числах, перед тире и после коротких слов;
  - меню и единое правило видимости секций (`nav.ts`);
  - ссылки на телефон, почту, мессенджеры и карты (`links.ts`);
  - экранирование (`html.ts`).
- **`src/pages/[...lang]/`** — одна страница на все языки:
  - `/` и `/consultation/` — русский;
  - `/uz/…` и `/en/…` — другие языки.

  Все адреса — под базовым путём `/PD/`. Страница `404.astro` только на русском.
- **`src/styles/tokens.css`** — токены из Figma: коллекции `Color · Light` / `Color · Dark` превращены в `:root[data-theme="light|dark"]`, плюс отступы, радиусы и шрифтовая шкала.
- **Тема:**
  - по умолчанию берётся из системы и следует за её изменением, пока пользователь сам не выберет;
  - выбор хранится в `localStorage` (`pd-theme`);
  - встроенный скрипт в `Base.astro` ставит тему до отрисовки, чтобы не было мигания.
- **Язык.** Выбор языка хранится в `pd-lang`. При открытии страницы на другом языке (без `#якоря` и не 404) скрипт перенаправит на запомненный язык, сохранив параметры адреса (например, UTM-метки).
- **Переходы без перезагрузки** — Astro `ClientRouter`. Обработчики кликов в `src/scripts/ui.ts` делегированы на `document`, а код для конкретной страницы запускается на `astro:page-load`. Долгоживущие элементы (свечение, плавающие кнопки) помечены `transition:persist`.
- **Свечение за курсором** — `src/scripts/glow.ts` и `src/components/Glow.astro`:
  - WebGL-шейдер на одном canvas рисует «жидкое» пятно из цепочки 4 метаболлов: голова тянется за мышью с инерцией, остальные следуют за ней, форма «дышит» за счёт шума;
  - реагирует только на мышь. Пока мыши нет (сенсорные экраны, до первого движения, после ухода курсора из окна), пятно медленно плавает по экрану;
  - на сенсорных устройствах — 30 кадров в секунду и пониженное разрешение canvas;
  - при `prefers-reduced-motion` стоит неподвижно; на скрытой вкладке анимация останавливается;
  - без WebGL используется запасной CSS-градиент;
  - цвет и яркость задаются токенами `--glow-color`, `--glow-peak`, `--glow-opacity` в `tokens.css`.
- **`tools/figma-bridge/`** — локальный мост к Figma (в сайт не входит). Он запускает скрипты из `tools/figma-bridge/scripts/` внутри Figma и складывает результаты (JSON и PNG) в `jobs/`, которые не попадают в git.

  Запуск:
  1. `node tools/figma-bridge/server.js`;
  2. в Figma desktop: Plugins → Development → Import plugin from manifest → `tools/figma-bridge/plugin/manifest.json`, затем запустить плагин PD Bridge;
  3. `node tools/figma-bridge/run.js tools/figma-bridge/scripts/<скрипт>.js`.

  Логотип и фавиконы выгружены скриптом `export-logo.js`.

## Публикация

`.github/workflows/deploy.yml` запускается:
- на каждый push в `main`, в том числе на каждое сохранение в Pages CMS;
- вручную;
- 1-го числа каждого месяца в 01:00 UTC (06:00 по Ташкенту), чтобы обновлялись стаж и год в подвале. GitHub отключает расписание в публичном репозитории после 60 дней без активности; тогда запустите публикацию вручную или включите расписание обратно во вкладке Actions.

Шаги: проверка контента → проверка формы CMS → проверка типов → тесты контента → сборка → смоук-тест в браузере → публикация на GitHub Pages.

Если какой-то шаг не прошёл, публикация не выполняется, на сайте остаётся прошлая версия, а в Summary запуска появляется отчёт:
- ошибки контента — таблица «Где / Что не так» и аннотации `::error`;
- предупреждения — таблица «Можно улучшить»;
- технический сбой — сообщение «отправьте ссылку разработчику».

Нужные настройки репозитория:
- **Settings → Pages → Source: GitHub Actions.**
- **Строгий режим перед запуском:** Settings → Secrets and variables → Actions → Variables → `CONTENT_STRICT` = `1`. После этого заглушки телефона, мессенджеров, формы и адреса не дадут опубликовать сайт.

## Pages CMS

1. Войти на https://app.pagescms.org через GitHub владельца репозитория и установить приложение Pages CMS на `wiut00012803/PD`.
2. Открыть проект: разделы и поля берутся из `.pages.yml`.
3. Collaborators → пригласить заказчика по email; GitHub-аккаунт ему не нужен.

## Свой домен

1. Задать переменные окружения сборки: добавить `env: { SITE_URL: https://домен, SITE_BASE: / }` к шагу «Сборка сайта» в `deploy.yml`.
2. В Settings → Pages указать домен, прописать DNS-записи по инструкции GitHub и включить «Enforce HTTPS».
3. Поправить адрес sitemap в `public/robots.txt`.

После смены базового пути локальный адрес станет `http://localhost:4321/`, а для `npm run shots` нужно задать `SHOTS_URL`.
